# Experience First

> **Apply when:** Making tradeoffs between user / developer experience and internal implementation convenience.

Prioritize user delight and intuitive ergonomics over internal implementation ease.

## Core Rules

1. **Clean public interfaces.** Never expose internal complexity, leaky abstractions, or cryptic error codes to end users or API consumers just because it was easier to code.
2. **Clear, actionable diagnostics.** When an error occurs, explain what failed, why it failed, and how the user or developer can resolve it immediately.
3. **Ergonomics over purity.** If an interface feels clunky or verbose to use every day, redesign the calling convention.
